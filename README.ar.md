## 🌟 نظرة عامة

وصلة سوق توصيل بوجهين للتجار ولأي شخص يريد إرسال أو استلام طرد. العميل ينشر نقطة استلام ونقطة تسليم. السائقون القريبون يستلمون الطلب، يكملونه بمسح QR، ويُقيَّمون. فريق التشغيل يدير المنصة من لوحة عربية RTL. مندوبو المبيعات يوسّعون الشبكة برموز إحالة.

هذا ليس نسخة من تطبيقات طلب الطعام. التطبيق مصمّم لـ **النقل العام من نقطة لنقطة** — برسوم تُحسب على الخادم، ومطابقة حسب المركبة، وتسليمات مجمّعة، ومسار اعتماد حقيقي قبل أن يرى السائق أي عمل.

---

## 🧠 الميزات التي تميّزه

### 🗺️ 1. إنشاء توصيل بدون عراك مع الخريطة
الاستلام والتسليم بثلاث طرق: لصق **رابط Google Maps**، إسقاط دبوس، أو الموقع الحالي. التطبيق يحوّل الرابط إلى إحداثيات، يرسم المسار، ويعرض المسافة والوقت المتوقع قبل التأكيد.

* **توقيت يسعّر نفسه:** عاجل، لاحقاً اليوم، أو خلال يومين — كل خيار برسوم إضافية تضبطها المنصة.
* **مجمّع دفعة واحدة:** استلام واحد، حتى 10 تسليمات، سائق واحد للدفعة. التسليمات الإضافية يمكن أن تُخصم تلقائياً.
* **تعديل وهو مفتوح:** تغيير المسار، إضافة/حذف تسليمات، أو إلغاء رجل واحدة — الباقي يُعاد تسعيره على الخادم.

### 💰 2. رسوم لا يستطيع العميل تزويرها
إنشاء / تحديث / إلغاء الطلب وقبول الدفعة تتم عبر **Cloud Functions قابلة للاستدعاء**. الخادم يقرأ إعداد التسعير الحي، يلتقط لقطة الرسوم، ويكتب الطلب. العملاء لا ينشئون مستندات الطلب مباشرة.

* **نموذج المسافة:** رسم أساسي + لكل كم (مسافة الطريق، مع احتياطي خط مستقيم).
* **منطقة ثابتة:** داخل عمّان الكبرى مقابل خارجها — رقم واحد بلا حساب كم.
* **عملة حسب الدولة:** دينار أردني أو جنيه مصري حسب حساب المستخدم.

### ✅ 3. الإتمام مسح QR، وليس زراً
بعد تأكيد الاستلام يعرض العميل رمزاً. السائق يمسحه لإغلاق التسليم. هذه هي عملية الإتمام — وليست ضغطة يمكن لأي أحد أن يكررها.

* العميل يستطيع **قبول أو رفض** السائق الذي طالب بالطلب.
* أي طرف يتصل بالآخر من شاشة الطلب.
* بعد الرحلة: تقييم السائق. نجمة واحدة يمكن أن تخفي طلبات هذا العميل المستقبلية عن ذلك السائق.

### 🛵 4. السائق يرى فقط ما يستطيع تنفيذه
عند الاتصال بالإنترنت التغذية مفلترة مسبقاً: نوع المركبة، نطاق التوزيع، ومن يطلبون محجوبون اختيارياً. الطلبات المجمّعة بطاقة واحدة — عدد التسليمات + إجمالي الرسوم — قبول الكل أو لا شيء.

* شاشة انتظار حتى **موافقة المشرف**. لا سائق غير معتمد على الطريق.
* كيلومترات وأرباح اليوم بنظرة، مع إحصاءات كاملة (اليوم / الأسبوع / الشهر / الكل).
* هوية ورخصة ووثائق حسن سيرة أثناء الإعداد.

### 🖥️ 5. التشغيل يدير المنصة فعلاً
لوحة المشرف Next.js عربية RTL — وليست وحدة تحكم Firebase بخطوات إضافية.

* نظرة عامة: طلبات اليوم، إيرادات الرسوم المكتملة، معدل الإكمال، شريط «يحتاج إجراء» (سائقون معلّقون، عملاء معلّقون، طلبات مفتوحة).
* اعتماد / سحب اعتماد السائقين. تفعيل / تعليق العملاء.
* أرباح كل سائق. عمولة كل تاجر مع إيصالات وسجل دفع.
* مفاتيح حية لنموذج التسعير، رسوم التوقيت، خصم المجمّع، نطاق التوزيع، وأرقام الدعم داخل التطبيق.

### 📣 6. النمو رمز إحالة، وليس جدولاً
**مندوبو مبيعات** ينشئهم المشرف: رمز شخصي، لوحة للمحالين من سائقين وتجار، وفترة عمولة يمكن تحصيلها. العميل والسائق يدخلان الرمز مرة واحدة. المشرف يفك الربط ويعيد الإسناد عند الحاجة.

## 🛠 التقنيات والبنية

* **الإطار:** Flutter (Dart) — عربي وإنجليزي، خط Cairo، جاهز لـ RTL
* **إدارة الحالة:** `hooks_riverpod`
* **التنقّل:** `go_router` مع بوابة من 4 مراحل (التعريف → الدخول → الدور → الإعداد)
* **الخلفية:** Firebase Auth، Firestore، Storage، Cloud Functions، FCM
* **الخرائط:** Google Maps / Places / Routes — ولصق رابط خرائط ← إحداثيات
* **المشرف:** Next.js، لوحة عربية RTL
* **البنية:** Feature-first (`lib/features/*`) + بنية مشتركة (`lib/core/*`)

الدخول عبر Google، أو البريد وكلمة المرور (مع بوابة تحقق البريد)، وOTP بالرسائل. تحقق الهاتف ورفع الوثائق قبل العمل الحقيقي. مفتاح إيقاف عن بُعد يمكنه قفل التطبيق إذا حدث خطأ في الإنتاج.
